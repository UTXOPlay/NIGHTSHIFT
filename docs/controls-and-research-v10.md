# NIGHTSHIFT control update and reference review — 30 October 2026

## Delivered in 10.0.2

Standard-mapped Gamepad API controllers can steer, brake/drift, reverse, boost, attack, counter and pause. Directional navigation follows the spatial arrangement of actual visible buttons, including map/vehicle thumbnails and modal settings; A selects and B returns. Ability glyphs follow the active input source. The current V8–V10 rules retain automatic throttle; RT is boost, not an invented independent accelerator.

Sticks use an 18% rescaled deadzone. New controllers and controllers returning from pause, portrait gating or keyboard/touch takeover must become neutral before arming. Holding Pause cannot repeatedly resume play. The active controller owns input until a deliberate input change; another controller cannot take over on disconnect. Disconnect pauses the local race and flushes ordinary native inputs. Unmapped devices are ignored instead of guessing button positions. Browser audio policies can require a keyboard press or tap to unlock sound; the settings explain this.

A compact, dismissible three-step practice guide observes actual game transitions: twenty moving steering ticks, ten braking ticks with a speed decrease, then a real native boost activation. It saves local instructional progress without granting currency or changing race rules. It hides for roadblock and incoming-attack warnings, paused simulation and portrait gating. Settings can restart practice. Existing keyboard, Colemak, remapping, touch joystick and reduced-motion paths remain available.

This presentation/input update does not change native sources, the exact V10 profile, signed career rules or executable hashes. An isolated source snapshot of the deployed 10.0.1 release is the build base. Concurrent V11 physics/career/fleet drafts are excluded. Only two existing served files change (the application bundle and HTML); four small source/style files are added. The renderer, art, sound and all existing raw rules modules remain byte-identical to the verified 10.0.1 release.

## Verification boundary

115 Node/host tests pass. Chromium exercises controller polling with virtual standard Gamepad API readings; no game/save state is edited by that review. Both desktop and touch-emulated runs complete practice, pause safely, yield to Colemak, navigate the garage, pause on disconnect and verify native signed replays. Touch emulation also verifies portrait cancellation. Separate acceptance covers all six required sizes, inverse pointer mapping, bounded backing pixels, actual earned purchases, a 3–7 minute race, results layout, English icon controls, trusted touch input and reduced motion. Physical-controller button labels/driver mappings, phone thermals and human driving feel remain unverified.

Machine-readable results are in [controls-results.json](controls-results.json). This update closes an implemented control/onboarding gap; it does not establish overall NFS parity.

| Driving | [Three.js Rapier vehicle example](https://github.com/mrdoob/three.js/blob/dev/examples/physics_rapier_vehicle_controller.html) separates engine force, brake force, wheel steering and suspension. [Unbound customization](https://forums.ea.com/discussions/need-for-speed-unbound-discussion-en/under-the-hood-show-up-and-show-off/9398276) gives grip/drift entry meaningful tuning. | V10 still auto-throttles in road-relative coordinates. A new exact profile must verify independent throttle/coast/brake, progressive grip loss and repeatable entry/apex/exit scenarios. Adding camera motion cannot satisfy this gate. |
| AI and combat | [Hot Pursuit manual](https://eaassets-a.akamaihd.net/eahelp/manuals/nfs-hp-remastered-switch-en.pdf) makes limited equipment, warning windows and counters legible. | Static roadblock parity is delivered in V10. Next measure whole-actor collision behavior, overtaking intent and braking decisions. Compare controller policies rather than merely increasing weapon damage. |
| Event pacing | [Unbound's official introduction](https://forums.ea.com/discussions/need-for-speed-unbound-discussion-en/under-the-hood-welcome-to-need-for-speed%E2%84%A2-unbound/9397714) ties races to a larger sequence and stakes. | Preserve 3–7 minutes while distributing meaningful objectives across the route. The old audit's 210.7-second median post-style-target interval is historical evidence, not a freshly measured V10 result. Require sector-level native objectives, discipline-specific grading and full-race ordinary-input evidence. |
| Career and shop | [Official customization article](https://forums.ea.com/discussions/need-for-speed-unbound-discussion-en/under-the-hood-show-up-and-show-off/9398276) connects parts, handling and garage access. | Current ranks and milestones are read models. Genuine unlocks and setup tradeoffs must be native rules, preserve earned ownership and expose exact admission/price effects in the shop. Avoid accidental grind or soft-locks. |
| Courses and world | [Starter Kit Racing](https://github.com/mrdoob/Starter-Kit-Racing) is a small inspectable track/game structure, not proof of an AAA open world. | Existing twelve corridors have distinct bends. Route choice needs actual branch geometry, collision and native progress semantics; background variations alone do not add a shortcut. |
| Art and audio | [Unbound customization](https://forums.ea.com/discussions/need-for-speed-unbound-discussion-en/under-the-hood-show-up-and-show-off/9398276) treats effects and engine identity as parts of vehicle expression. | 10.0.1 has credited recordings and six mixes, but still only two base car meshes and one shared engine recording. Require licensed distinct silhouettes, material coherence and authored landmarks; do not call a new tint a new vehicle model. |
| Controls and teaching | [Gamepad API documentation](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API) requires polling current readings. | 10.0.2 adds standard mapping, neutral rearming, menu navigation and observed practice. Remaining acceptance includes physical controllers, real phones and instructional usability. |
| Engine and future online | [ecctrl](https://github.com/pmndrs/ecctrl) separates vehicle/control concerns around a physics body. | Reuse architecture ideas, but preserve deterministic native/browser rules. Do not insert a browser-only floating-point engine into signed replay. Shared authoritative matches still need clock/input ordering, reconciliation, reconnects and exactly-once rewards; current product is solo. |

All references are primary publisher/developer sources. The comparison and acceptance gates are our own design judgments.
