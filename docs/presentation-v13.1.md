# Deferred graphics and coherent circuit assets — NIGHTSHIFT 13.1.0

The career menu now uses captures of the actual twelve courses, with responsive 384/768/1280/2560 px variants. Opening it creates no WebGL context and fetches no vehicle, HDR or lighting-probe data. The garage loads its selected car and studio probe; entering a race prepares the selected environment, player body and bounded common traffic/effects. Independent asset requests run together. Shader compilation and the first shadow/postprocess draw finish before the starting countdown.

Six transparent vehicle thumbnails are renders of the actual licensed fleet. They replace the shared vector-car fallback in both initial and garage-only loading paths. All six hero rigs have four tire contact points at the showroom floor. VANTA retains the original UVs, materials, panel geometry and normal maps in its showroom model. Its race model retains the exterior and wheel hierarchy with bounded simplification, omitting hidden mechanical/interior pieces. Meshopt compression and texture packing reduce the authored source from 5,300,584 bytes to 3,301,716 bytes for the hero and 1,757,172 bytes for the race model. These are source-file sizes, not HTTP transfer or GPU-memory measurements. The other four source bodies retain their existing prepared surface pipeline; further vehicle-material unification remains open.

An ImageGen atlas adds two variants for each of eight facade families. Masonry, glazing, occupied rooms and roof response are separate. Structures use material scale in metres; light fixtures have varied metal finishes, warm/cool diffusers and two bounded nearby physical lights. Neon/night environments have a separate generated harbour skyline. Generation records and packing parameters are in [the asset report](presentation-v131-assets.json) and [prompt records](presentation-v131-prompts.json); the facade prompt is explicitly marked as a reconstructed brief. Route and fleet previews are actual renders, not generated depictions of unimplemented content.

Four HDR probes are convolved offline and loaded on demand. Only the selected route's foliage/terrain, backdrop and signs are prepared. The wet-road reflection pass now excludes its receiving road, preventing a framebuffer/texture feedback loop. Effects retain their generated artwork with bounded atlas sizes. The complete credited music track remains 199.4 seconds; the delivery encode omits frequencies already removed by the gameplay mixer.

The legacy interception caption follows its original rules; only V13 appends the podium requirement. Recovery hints reference the independent foot brake for V12+. Recovery also has a restrained visual/audio cue. No driving, collision, combat, rewards, progression, replay or save rules change. All V8–V13 binaries and application profiles remain frozen; Myelin remains off-chain host replay, not CKB settlement. Multiplayer is not implemented by this release.

## Performance interpretation and remaining work

Local cold menu samples are approximately one second on desktop and 2.1 seconds with 4 Mbps / 120 ms / 4× CPU emulation. The emulated first race remains much slower, around 28 seconds including resource delivery and countdown in an intermediate sample. Loading is therefore not declared complete. Local figures cannot be compared directly with the prior public-origin 22.47-second cold menu sample. Public cold/repeat/menu-to-race measurements must retain their actual network/cache conditions and exclude no mandatory phase.

The full single-player objective remains active. Fair continuous-line opponent planning, stronger racing/combat decisions, consistent damage semantics, route decisions, close-scenery geometry/lighting coherence, secondary-car material detail, audio identity, further weak-network startup work and the final completion audit remain required. Changes to native rules require a separately bound V14 implementation and retained V13 origins; none may be slipped into this presentation release.

Private preview diagnosis: a 666,487-byte compressed lighting probe took 13.63 seconds through the SSH tunnel; the staged service returned its decoded representation in 60 ms when requested inside the server. The first preview timeout therefore did not establish a renderer deadlock. A later continuous driving check reached the existing pending-input pause and tried to click the hidden race HUD. The pause/confirmation/resume flow is now explicitly tested; functional timeout overrides do not change loading benchmarks or the game's network protection. Retaining the reason for a connection-triggered pause after confirmation remains an interface follow-up.

The asset tools are offline development dependencies. To reproduce the compressed VANTA models, install the exact versions listed in `fleet-v131/provenance.json` into `artifacts/presentation-v13/asset-tools`, then run `node tools/prepare-fleet-v131.mjs` and the same command with `--race`. Normalized/interleaved attributes are expanded before CPU rig transforms. `bake-nightshift13-probes.mjs`, `bake-nightshift13-maps.mjs` and `bake-nightshift13-fleet.mjs` reproduce the corresponding runtime captures. Their licenses ship with the browser assets.

## Public 13.1.0 delivery and the save-latency follow-up

Version 13.1.0 was deployed from source `3c7a7cb42d8b2c12af9f831b74250fc348aafd02`. Public real-asset checks passed all nine presentation cases, five touch cases, desktop/touch virtual-controller practice and Colemak takeover, native signed replay, and Store fullscreen exit/reentry with the same iframe instance. Its source and native GitHub checks passed. Deployment and experiment records, including failed attempts, are retained in [the results](presentation-v131-results.json).

One public desktop sample loaded the menu in 5.24 seconds, with a 1.90-second repeat; a separate cold-race sample reached driving 20.90 seconds after navigation, including 17.32 seconds after selecting the race. The 4 Mbps / 120 ms / 4× CPU mobile sample reached its menu in 3.21 seconds and driving 32.76 seconds after navigation. These are samples, not percentile guarantees or physical-device measurements. First-race delivery remains unfinished.

A 20-second public driving sample passed at 60 median / 60 p10 FPS. A longer attempt paused after 48.23 seconds with 90 queued inputs, an outstanding save and no browser error or wreck; the renderer still reported 60 FPS. This identified the existing short save-buffer limit as a separate sustained-play problem. No passing 120-second result is claimed for 13.1.0.

The 13.1.1 candidate prioritizes native API fetches, catches up with the existing native limit of 120 inputs per request, and bounds the queued solo inputs at 300 (ten seconds at 30 Hz), plus one in-flight batch. A longer outage still pauses simulation. Confirmation then explicitly tells the driver that the saved race can resume. Four-second save latency, bounded long-outage pause, exact confirmation, same-race resumption and signed replay are covered by `tools/nightshift13-connection-review.mjs`. These are solo transport/presentation changes; physics, reward rules, application profiles and all six native binaries are unchanged. This buffering policy is not a multiplayer synchronization design.
